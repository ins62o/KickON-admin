# 요구사항 상태

기준: 사용자가 제공한 KickON Data Center 명세. 후속 사용자 결정인 선수 사진 제외와 현재 navy/blue 색상 유지가 원 명세보다 우선합니다.

원격 Supabase migration은 이 작업에서 적용하지 않았습니다. 따라서 코드·SQL 구현과 실제 개발/운영 환경 적용 상태를 분리합니다.

| 영역 | 코드 상태 | 외부 적용/검증 |
| --- | --- | --- |
| 9개 메뉴와 관리자 전용 `/` | 구현 | 관리자 계정별 접근 테스트 필요 |
| 고정 상단 헤더·가로 메뉴, 다크 기본·라이트 선택 | 구현 | 브라우저 회귀 필요 |
| 역할별 메뉴와 서버 권한 재검사 | 구현 | `admin_users` 새 역할 적용 필요 |
| 운영 대시보드 집계 | 구현 | `admin_get_dashboard_metrics` 개발 DB 적용·권한 검증 필요 |
| 사용자 검색·활동·신고·제재 상태 | 구현 | `admin_get_users` migration 적용 필요 |
| 문의 목록·상세·답변·내부 메모 | 구현 | 문의 답변/메모 migration 적용 필요 |
| 신고 원문·누적 신고·숨김/복원 | 구현 | 콘텐츠 정책 migration 및 모바일 회귀 필요 |
| 사용자 경고·정지·해제 | 구현 | 제재 정책 migration 및 모바일 쓰기 차단 검증 필요 |
| 선수단 목록·한글 검증명·수동 보호 | 부분 | 기존 상세 보정 흐름 유지. 새 수동 선수/검증명 RPC 적용·화면 보강 필요 |
| 선수 사진 미사용 | 구현 | DB 컬럼은 모바일 호환을 위해 유지 |

| 동기화 실행·기록·오류 | 구현 | Edge Function secret과 개발 실행 검증 필요 |
| DB/파일 Storage 선택 게이지 | 구현 | 버킷·이번 달 증가·큰 파일·70/85/95% 경고 포함. Metrics/Storage server key와 플랜 한도 필요 |
| SportsMonks 사용량·엔드포인트·실패 | 구현 | 60일·엔티티 quota·429/4xx/5xx 포함. 실제 호출 로그와 allowance 필요 |
| 시스템 상태 | 구현 | 외부 서비스/cron/push 관측 연결 필요 |
| 관리자 감사 로그 | 구현 | 새 RPC 변경 기록 검증 필요 |
| 전역 검색 | 구현 | 역할별 결과·민감정보 최소화 회귀 필요 |

## 의도적으로 하지 않은 것

- 임의 샘플 수치로 정상 상태를 만들지 않습니다.
- 콘텐츠를 관리자 화면에서 하드 삭제하지 않습니다.
- 선수 사진·이니셜 아바타를 표시하거나 수정하지 않습니다.
- 서비스 역할 키와 외부 API 토큰을 클라이언트에 노출하지 않습니다.
- 기존 모바일 migration과 충돌 가능성을 무시하고 원격 DB에 자동 적용하지 않습니다.

3. 첫 `super_admin`과 역할별 테스트 계정을 안전하게 등록합니다.
4. 문의·제재·숨김·선수 잠금·동기화·감사 흐름을 E2E로 검증합니다.
5. 모바일 앱의 게시글·댓글·응원·선수단·순위 흐름을 회귀 테스트합니다.
6. 별도 승인 뒤 운영 승격을 진행합니다.
