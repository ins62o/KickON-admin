# 경기 후 처리 범위 수정 및 관리자 재시도

운영 기존 배포 소스를 내려받아 기준 SHA를 보존하고 그 소스에서 수정. 개발 수집기는 별도 구형 경로여서 덮어쓰지 않음

## 원인과 수정
- 기존 경기 후 처리가 시즌 전체 경기 198개·272개를 저장하려고 시도. 다른 실시간 상태 전이까지 처리하려다 종료 전용 보호 경로와 충돌해 BLOCKED 유지
- 운영 2026 미처리 8경기(리그1 5개, 리그2 3개)의 DB 종료·처리 기한·미처리 조건과 공급자 종료 상태·스코어·구단 연결을 확인
- post-match만 보완 대상 종료 경기로 저장 범위를 제한. 진행 경기·향후 일정·기처리 경기 제외. DB의 기존 경기/득점/알림 보호 함수와 historical 경로는 수정하지 않음

## 버튼
- 운영 ‘경기 후 데이터 갱신’ 오류 모달에 데이터 변경 권한이 있는 관리자용 ‘원인 재확인·재시도’ 추가
- 다른 리그·시즌·작업·읽기 전용 계정의 요청은 거부
- 두 리그 공급자 근거를 먼저 전부 확인한 후 세대·현재 오류 코드·정확한 경기 ID·활성 작업·요청 ID를 검사하는 서비스 전용 RPC로 접수
- 기존 오류는 접수 시 지우지 않고, 정상 worker 완료 후에만 해소
- 접수·대기·다른 실행·오류·실제 완료를 구분하며 실행 원장과 변경 전후 감사를 남김
- 중복과 오래된 요청이 새 처리를 시작하지 못하도록 보호

## 확인 결과
- Node 211개, SQL 재시도 권한/스코프/세대/이중 접수/큐 실패 전체 롤백/감사/가짜 완료 차단 테스트 통과
- 브라우저 모달·권한·단일 요청·로딩/닫기 잠금·모달 토스트·접수 후 오류 유지 6개 통과
- 린트·타입 검사·빌드 통과. 운영 worker와 API의 무인증 401 확인
- migration 202610200025 및 운영 worker/API 배포. 기존 비밀 값 변경 없음

## 실제 재처리 승인 대기
자동 승인 검토가 운영 8경기 실제 재처리를 거절. 사유: 사용자 요청은 차단 원인 수정과 버튼 추가이며 즉시 운영 재처리까지 명시 승인한 것은 아니라는 판단
재처리 SQL은 실행하지 않았음. 두 범위는 여전히 BLOCKED(세대2/7), 실제 성공·8경기 완료를 주장하지 않음
prepared-recovery.sql은 정확한 기존 검증 함수 해시·두 차단 before-image·8개 경기 ID가 그대로일 때만 접수하도록 준비. 별도 실행 승인 후 최신 공급자 근거/원장/동시 처리 조건을 재확인해야 함. 승인 전 실제 버튼 자동 클릭이나 다른 경로로 실행하지 않음
