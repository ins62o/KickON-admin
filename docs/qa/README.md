# KICKON Admin QA 실행 및 자료 보존

이 문서를 QA 실행 규칙의 단일 기준으로 사용한다. 기존 운영 승인·PAUSED/HOLD/UNKNOWN 상태를 변경하지 않는다.

- 재사용 가능한 테스트 코드·명시적으로 가짜인 Fixture·Helper는 Git에서 관리한다
- 테스트·lint·빌드 로그는 접근 제한된 임시 경로에 저장한다
- 일반 QA 로그·JSON·스크린샷·영상·HTML 리포트는 임시 자료로 관리하고 기본적으로 Git에 추가하지 않는다. 실제 사용자·Secret 포함 가능성이 있으면 원문을 출력하지 않고 제한된 외부 경로에 보존한다
- QA 결과를 확인한 뒤 해당 작업이 생성한 임시 파일만 삭제한다. 기존 자료나 다른 작업의 파일은 임의로 정리하지 않는다
- 실패 원인 분석에 필요한 재현 자료는 해결·확인까지 유지한다
- 날짜별 QA 결과 폴더를 영구적으로 누적하지 않는다
- 일반 QA 결과는 사용자에게 간결하게 보고하고 저장소에 별도의 일일 QA 보고서를 만들지 않는다
- 운영 장애·배포 승인·Migration·복구 증거는 일반 QA 정리 대상에서 제외하고 기존 보존·승인 규칙을 따른다
- 테스트 이름만으로 오프라인을 가정하지 않는다. 네트워크·DB·자식 프로세스·파일쓰기 영향을 검토하고 격리한다
- Vite 설정 로드의 SQLite 초기화와 preview의 실제 지표 수집을 차단하지 못하면 실행하지 않는다
- 원격 실행·운영 데이터 변경·테스트 Push·Wake·Retry·배포는 별도 명시 승인 범위에서만 수행한다
- Git ignore는 비밀정보 보호나 빌드의 public 자산 복사를 보장하지 않는다

이 정책은 기존 QA·운영 자료의 일괄 삭제 또는 과거 Git 이력 재작성을 승인하지 않는다.
