# 로그아웃 후 운영 환경 재로그인 수정

## 원인과 수정

운영 배포 workflow에만 `KICKON_LOGIN_ENVIRONMENT=development`가 지정되어 있었다. 로컬 development·production 모드에는 이 값이 없었으므로 `?environment=production`에서 로그아웃 후 로그인하면 운영 프로젝트에 비밀번호 인증을 요청했다. 운영 계정은 일회성 인증으로 접속했던 기존 관리자여서 비밀번호가 등록되지 않은 경우 실패했다.

공개 개발 연결이 구성되어 있으면 공통 로그인은 개발 연결을 기본으로 사용한다. 운영만 구성된 설치는 운영 연결을 사용하고, 명시적인 로그인 환경 설정이 있으면 이를 우선한다. 로그인 대상 작업 환경과 관계없이 인증 기준을 유지한다. 인증 후 대상 환경의 동일 이메일·활성 관리자 권한을 확인하는 기존 서버 교환 및 양쪽 로그아웃 정책은 유지한다. 계정 생성이나 비밀번호 변경은 하지 않았다.

## 검증

- 구성 회귀 테스트: 별도 로그인 환경 설정 없이 development·production 모드 모두 동일 개발 인증 연결 선택, 운영 단독 구성 및 명시적 재정의 검증
- 단위 테스트 212개 통과, lint·타입 검사·Vite 빌드 통과
- 실제 앱과 Supabase SDK를 사용하는 브라우저 테스트: 운영 작업 환경 진입, 3회 로그인과 양쪽 로그아웃, 로그아웃 후 새로고침 및 재로그인, 대상 권한 거절 시 양쪽 세션 삭제
- 외부 인증과 관리자 API 응답은 모의 처리했으며 실제 사용자 비밀번호 로그인은 수행하지 않았다
- 인증 로그 조회는 Management API의 analytics_logs_read 권한 부족으로 불가하여 실제 실패 요청의 서버 오류 코드는 확인하지 못했다
